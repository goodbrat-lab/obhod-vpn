## 🚨 Критические проблемы безопасности

### 1. **Path Traversal уязвимость** (Критический)
**Местоположение**: `internal/config/generator.go:300`
```go
path := filepath.Join(RulesDir, userTag+".json")
```
**Проблема**: Отсутствие валидации `userTag` позволяет доступ к системным файлам
**Пример эксплуатации**: `../../../../etc/passwd`
**Риск**: Чтение/запись системных файлов
**Решение**: 
```go
func sanitizePath(filename string) string {
    // Белый список разрешенных символов
    reg := regexp.MustCompile(`[^\w\-\.]`)
    return reg.ReplaceAllString(filename, "")
}
```

### 2. **Command Injection в DNS проверках** (Критический)
**Местоположение**: `internal/sysinfo/sysinfo.go:54`
```go
data, err := exec.Command("cat", path).Output()
```
**Проблема**: `path` не валидируется перед выполнением
**Риск**: Выполнение произвольных команд
**Решение**:
```go
func safeReadFile(path string) ([]byte, error) {
    // Валидация пути
    if !filepath.IsAbs(path) || strings.Contains(path, "..") {
        return nil, fmt.Errorf("invalid path")
    }
    return os.ReadFile(path)
}
```

### 3. **Race Condition в Watchdog** (Высокий)
**Местоположение**: `internal/watchdog/watchdog.go:68-76`
```go
failCount++
if failCount < maxFails {
    continue
}
```
**Проблема**: Отсутствие синхронизации при доступе к `failCount`
**Риск**: Непредсказуемое поведение системы
**Решение**: Добавить `sync.Mutex`

### 4. **Hardcoded Secrets** (Высокий)
**Местоположение**: `internal/telegram/telegram.go`
```go
Token: token, ChatID: chatID
```
**Проблема**: Секреты в открытом виде
**Риск**: Компрометация Telegram бота
**Решение**: Хранить в UCI с шифрованием

## 🔍 Анализ архитектурных проблем

### 1. **Смешанная архитектура**
- **Гибридная архитектура**: Go бэкенд + Bash фронтенд
- **Проблема**: Разные парадигмы программирования
- **Последствия**: Сложность отладки и поддержки

### 2. **Отсутствие атомарности операций**
- **Проблема**: Изменение конфигурации не атомарно
- **Риск**: Неконсистентное состояние при сбоях
- **Решение**: Реализовать transaction-like pattern

### 3. **Memory Management**
- **Проблема**: Неограниченное выделение памяти при парсинге подписок
- **Местоположение**: `internal/subscription/fetcher.go:66-90`
- **Риск**: OOM на роутерах с малой памятью
